Observed Windows failure
- Command: sh_run_step030_acceptance
- Failure occurred while importing fastapi.testclient.
- Exception: ModuleNotFoundError: No module named 'fastapi'.
- No STEP030 acceptance workspace or Product result was produced.

Code-audited root cause
- sh_setup.cmd correctly creates .venv and installs the project with .venv\Scripts\python.exe.
- STEP029 and earlier launchers invoke the project .venv Python.
- sh_run_step030_acceptance.cmd alone invoked bare PATH `python`.
- scripts/windows_entrypoint.py then inherited that interpreter through sys.executable.
- The failure was therefore a launcher regression, not a STEP030 business-contract failure.

Implemented correction
- sh_run_step030_acceptance.cmd now fails closed when .venv\Scripts\python.exe is absent.
- It invokes only `.venv\Scripts\python.exe scripts\windows_entrypoint.py commerce-snapshot-non-empty-acceptance`.
- Added a project-wide test forbidding bare Python in every runtime Windows launcher.
- Added STEP030A deterministic acceptance with eight exact launcher/dependency/baseline checks.
- No business model, ingress, payload, Task/Run, Artifact, Evaluation, Tool, MCP, source, or authority behavior changed.
